# Known bugs: the ledger

Every bug that was fixed after a player (or a hunt, review or audit) met it gets one stable id here,
`KB-nnn`, one plain-words line of what the player saw, the round it was fixed in, and the test that now
holds it. If a line here ever fails, an old bug is back.

Ids never change and are never reused. Add new ones at the end.

## Line format

    KB-nnn | source id | what the player saw, one line | fixed in round | tests/path/file_test.lua :: exact test name

- **source id**: the id the bug had in the bug lists (AUD-, BRK-, REC-, HUNT-, ...), or `-`.
- **fixed in round**: the fix round (`r32`); the release version is not recorded for these, write it
  (`2.4.3`) when it is known. `round not recorded` is allowed.
- **last field**: a test file that exists in this repository, then ` :: `, then the exact name of a
  `test("...")` in it. For a Lab check use `lab/<file> :: <check name>`. If the test was not carried into
  this repository write exactly `test not in this repo` (never invent a path).

## Rules

- New bug fix: add the next KB id here in the same pull request, and **name the new test with the id**
  (for example `test("KB-118 a blocked rider ...", ...)`), so the id finds the test and the test finds the id.
- Older tests keep their names (many already cite their source id, such as AUD-14). Renaming them to cite
  the KB id is a follow-up, not done in bulk.
- `lua5.1 tools/known-bugs-check.lua` fails on a duplicated KB id, a malformed line, a test file that
  does not exist, or a test name that is not in that file. The suite runs it
  (`tests/tools/known_bugs_check_test.lua`).
- Not every old fixed bug is here yet. Bugs whose test is only named by round folder, or has no test
  that cites the bug, are left out until someone links them to a real test. Add them as you find them.
