## What Wuber is

A World of Warcraft (WoW Forever, Interface 16001) addon that treats a Warlock summon like a ride. A
rider sees which Warlocks are online, where they are and their price, and requests one with a click; a
driver (a Warlock running Wuber) sees a queue, summons, and gets paid in the trade window. There is no
server: drivers announce themselves on a chat channel and by whisper, and the clients gossip. Version
and history: `Wuber/Wuber.toc` (the version and the load order) and the git log. Older design notes (`SPEC*.md`, the refactor
notes) are not kept in this repository. Today the addon is 112 modules (the generated map below has the exact count).

New here? Read this intro, then `AGENTS.md` (rules and commands), then `tests/README.md` (how the fake game works and what it
cannot prove). To change a screen, find its module in the map, read the module's header block and its `Test:` file.

Top to bottom is also top to bottom in the TOC: `Core -> Net -> Theme/FX -> UI -> Drive -> UI/Driver`, then
`FX.Nameplates`, `FX.Emblem` and `UI.Commands` (the slash commands, last so everything exists). Rider flow:
`UI.Rider.Home -> Confirm -> Ride -> Done`, driven by `Net.Rides`. Driver flow: chat arrives in
`Drive.Chat`/`Drive.Queue`, `Drive.Service` runs the job, `Drive.Trade` sees the money, `UI.Driver.*` shows it.

## How modules talk

- **Registry.** Every file starts with a header block, then
  `local Mod = W.Module("Net.Discovery", { "Net.Base", "Net.Community" })`. The name is the file path with
  dots; the list is its hard dependencies. `W.Mod("Net.Base")` returns another module's private table (a handle).
  `Core.Registry` checks at login that every dependency exists and loads earlier.
- **Imports bind at load, from earlier modules only.** Right under the `W.Module` line:
  `local BaseMod = W.Mod("Net.Base")` then `local now, call = BaseMod.now, BaseMod.call`. Only for modules
  listed in the dependency list; the provider exports its locals at the end of its own file (`Mod.now = now`).
- **Late refs go through the handle at run time.** A module that needs a function from a module that loads
  LATER keeps `local HomeMod = W.Mod("UI.Rider.Home")` and calls `HomeMod.buildHome(...)` inside functions,
  never at load. These are the header's `Later:` line, not dependencies.
- **Hook slots** replace rebound state. A local that is reassigned and read elsewhere is never exported as a
  value; the owner exposes a slot or accessor (`Net.Base.onJoined`, `Net.Beacons.noteDirectory`) that the
  other module fills at load (the header says `sets X.y`). Nothing else may write into another module's table.
- **Events, not reach-ins.** Game events: `W.On("EVENT", fn)`. Wuber's own bus: `W.Listen("DRIVE_STATE", fn)` /
  `W.Fire(...)`. Login work: `W.OnLogin(fn)`. Handlers of one event run in TOC order, so moving a file can
  change behaviour (the internal refactor notes appendix A lists the order that must hold).
- **Public names never change.** `W.*`, `UI.*`, `DR.*`, `D.*`, `T.*`, `FX.*`, `W.Map.*`, `WuberAPI.*` keep their
  names and values wherever they are defined; the tests replace some of them at run time, so a call through a
  table must stay a call through that table.
- **Nothing runs at load** except locals, function definitions, table fields, `W.Module`/`W.Mod`, event
  registrations and a short allow-list (see `tools/check.lua`).

Where is the module for a task? Search the module list below for the screen, event or `W.` name; each entry
gives the file, what it does, its API, dependencies, events, test file and size. Read that module and its test,
not the folder.
